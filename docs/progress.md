  - **Settled with the owner (2026-10-18)**:
    - Native components wherever possible; the tokens connect where native allows.
    - **Colors**: asset-catalog color sets with light and dark, as Apple's [Dark Mode guide](https://developer.apple.com/documentation/uikit/supporting-dark-mode-in-your-interface) recommends; they fit, since colors change with the theme only (`pts/orthogonal-modifiers`). A custom plugin writes them from `resolver.apply` per theme, plus public Swift names (a package's assets aren't visible to an app by name; check Xcode's generated asset symbols). `@terrazzo/plugin-swift` 0.3.4 can't: it reads dark from `token.mode`, which under our resolver holds only `.` (checked), so it writes light only; it is the reference for the colorset JSON.
    - **Type**: Aspekta stays; sizes and rules are Apple's Dynamic Type ([custom fonts guide](https://developer.apple.com/documentation/swiftui/applying-custom-fonts-to-text): `Font.custom(_:size:relativeTo:)`). Apple's default sizes (body 17/22 …) are Apple's values, not tokens; the tokens only say which iOS text style each `text/*` follows. Fonts in a package register in code (`CTFontManagerRegisterFontsForURL`). SwiftUI sets line spacing, not line height.
    - **Platform knowledge goes in `$extensions`**, the DTCG format's place for team data (reverse-domain key, e.g. `"io.github.haaanju.pts": { "ios": { "textStyle": "title" } }`), with one resolver. The ADR must tell it apart from the `$extensions.mode` ban, which is about modes. Rejected: a `platform` modifier (it and viewport both change display sizes, against Terrazzo's orthogonality advice and `pts/orthogonal-modifiers`; 48 permutations, `ios × wide` among them), and one resolver per platform (neither [Terrazzo's resolver guide](https://terrazzo.app/docs/guides/resolvers/), which has one resolver with inputs set in plugin options, nor the DTCG resolver spec mentions it).
    - **No viewport on iOS**: the plugin fixes viewport to `narrow` (as products fix modifiers, ADR 0047) and writes no breakpoints; size classes (compact, regular, by window) and Dynamic Type do that job.
    - **Lint by platform, run together**: shared rules for all; web and Android keep `min-font-size`, `line-height-grid`, and `type-scale` (Apple's sizes break all three: 11pt, 22 line height, 17/15/13); new iOS rules (every `text/*` has a valid `textStyle`, maybe 44pt targets). All run in `npm run check`, so a shared token change can't break iOS unseen.

- Large containers may need more than `padding/xl` (20px since ADR 0052); buttons don't. The answer would be a new role token, not a larger `xl`.
- A literal-typed `tokens.d.ts` (ADR 0030) waits for a component whose properties take tokens (a Box or Stack); per ADR 0034 that component is added only as a fixture for it.
- Dark-mode letter spacing: light text on a dark page reads tighter, so fine-tune letter spacing in dark. That makes `letter-spacing` (and the `text/*` composites that use it) theme-dependent: it would move into the theme files, the dark CSS blocks, and the Figma `Theme` collection. Since ADR 0028, text sizes share `letter-spacing/normal` (0), so dark may need per-size text values too. Needs an ADR. Low value for its cost: keep it until dark text visibly needs it.
- Scheduled releases (owner, 2026-10-12): releasing stays merging the Release PR by hand, since releases are rare and the native demo needs one on demand.
