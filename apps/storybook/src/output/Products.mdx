<Section title="Usage" lead="Import a product's CSS instead of tokens.css, not both: each declares every token on :root. Its JS holds real values for charts, canvas, or anything that can't read a CSS variable.">
  <Source
    language="css"
    dark
    code={`@import "@pts/web/fonts.css";
@import "@pts/web/products/dense-app.css"; /* density compact, shape soft; no [data-density] or [data-shape] blocks */`}
  />
  <Source
    language="ts"
    dark
    code={`import { resolver } from "@pts/web/products/dense-app.js"; // typed by dense-app.d.ts

// Pass every modifier: the product's own density and shape, and the theme and viewport it leaves open.
const tokens = resolver.apply({ theme: "dark", density: "compact", viewport: "narrow", shape: "soft" });
tokens["padding.md"].$value; // ${JSON.stringify(token("padding.md", "dark", "compact").resolved)}
tokens["surface.subtle"].$value.hex; // "${token("surface.subtle", "dark", "compact").resolved.hex}"`}
  />

  - The JS holds one token set per theme × viewport at the product's density and shape, as Terrazzo's resolver gives them, with each token's `$type` and `$value` (the DTCG shape: a color has `hex` and `components`, a dimension `value` and `unit`).
  - `apply()` fills an omitted modifier with the resolver's default, so in plain JS `dense-app` needs `density: "compact"` passed too, and `roomy-app` `shape: "round"`; TypeScript requires every modifier.
</Section>
